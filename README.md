# 第一部分 · 零基础入门

## 1. 这个软件是干什么的？

**一句话回答**：把普通的图片（比如 PNG、JPG）转换成 Windows 图标文件（`.ico`）。

**稍微详细一点**：你在电脑上看到的每一个图标——桌面上的"此电脑"、文件夹、快捷方式、任务栏上的程序——背后都是一个 `.ico` 文件。这种文件很特殊，它里面**同时装着好几个不同大小的版本**（16×16、32×32……256×256），Windows 会根据你当前在哪看（桌面大图标、任务栏小图标、文件夹列表），自动挑一个合适的大小显示。

这个软件就是帮你把一张普通图片，"打包"成这样一个多尺寸的 `.ico` 文件。

**它不能做什么**（先说明白，避免误会）：
- 不能画图、不能编辑图片内容；
- 不能把 `.ico` 转回 PNG（虽然技术上可行，但这个软件没做）；
- 不能处理 SVG、HEIC、AVIF 这些新格式（Pillow 库打不开的都不行）。

---

## 2. 一分钟看懂：ICO 是什么？为什么要转换？

### 打个比方

把 ICO 想象成**一套俄罗斯套娃**：
- 最外面的是 256×256 的大娃（用于高清屏、大图标视图）；
- 里面套着 128、64、48、32、24；
- 最里面是 16×16 的小娃（用于任务栏、文件列表的小图标）。

Windows 打开这个"套娃"，看你需要多大的，就取哪一个。

### 为什么不直接用 PNG？

Windows 对图标文件有专门的格式要求。虽然现代的 Windows 10/11 也支持 PNG 压缩的图标（我们这个软件生成的正是这种），但：
1. 系统菜单、任务栏、老软件只认 `.ico` 扩展名；
2. 一个 `.ico` 能装多个尺寸，一个 PNG 只有一个尺寸；
3. 快捷方式、可执行文件、文件夹自定义图标，都要求 `.ico`。

所以：**PNG 是给眼睛看的，ICO 是给系统用的**。

## 3. 我要怎么打开这个软件？

有三种方式，任选一种：

### 方式一：双击 `1.bat`（推荐给普通用户）
项目根目录下有个 `1.bat`，双击它就能启动。
> 前提：电脑上装了 Python 3.10 左右的环境。如果没装，看方式三。

### 方式二：命令行运行
打开命令行（cmd 或 PowerShell），进到程序目录，输入：
```
python Image_To_Icon_Converter.py
```

### 方式三：用打包好的 exe（推荐给完全不想折腾的用户）
进入 `build_output\Image_To_Icon_Converter.dist\` 目录，双击 `Image_To_Icon_Converter.exe`。
> **注意**：这个目录里的所有文件都要在一起，不能只把 exe 单独拷出来——它旁边的一堆 DLL 和文件夹都是必需的。整个目录一起拷贝/分发。

## 4. 第一次使用：三步完成转换

### 第一步：选图片

点左侧的 **"选择图片文件"** 按钮：
- 可以一次选多张（按住 Ctrl 点选，或按住 Shift 选一段）；
- 支持的格式：PNG、JPG、JPEG、BMP、GIF。

或者点 **"选择图片文件夹(批量)"**：
- 选一个文件夹，软件会自动把这个文件夹（含子文件夹）里所有图片都列出来。

选完后，左边列表里会出现文件名，右边会显示第一张图的预览。

### 第二步：选输出位置

点 **"选择输出位置"** 按钮：

| 你的情况 | 会发生什么 |
|---|---|
| 只选了 1 张图 | 弹出"保存文件"对话框，让你指定 `.ico` 的完整路径和文件名 |
| 选了多张图 | 弹出"选择文件夹"对话框，所有 `.ico` 都存到这个文件夹里，文件名跟原图同名 |

### 第三步：点"开始转换"

点右下角的 **"开始转换"** 按钮。进度条会动，下面会显示"正在转换: 文件名"。转换完成后弹窗提示。

**大功告成！** 去输出位置就能看到 `.ico` 文件了。

# 第二部分 · 日常使用指南（适合所有职业）

## 6. 常见使用场景举例

### 场景 A：给桌面快捷方式换个漂亮图标（普通用户）
1. 网上找一张喜欢的图（PNG 最好，带透明背景）；
2. 用本软件转成 `my_icon.ico`，尺寸全选（默认）；
3. 右键桌面快捷方式 → 属性 → 更改图标 → 浏览 → 选 `my_icon.ico` → 确定。

### 场景 B：给公司软件做图标（设计师 / 开发）
1. 设计稿导出 1024×1024 的 PNG；
2. 用本软件转换，尺寸全选；
3. 把 `.ico` 交给开发，用于 exe 图标、安装包图标、任务栏图标。

### 场景 C：批量给一整套文件配图标（运维 / 行政）
1. 把几十张图标 PNG 放到一个文件夹；
2. "选择图片文件夹(批量)" → 选那个文件夹；
3. 选输出文件夹 → 开始转换；
4. 几十个 `.ico` 一次生成，文件名与原图对应。

### 场景 D：程序打包时生成配套图标（开发者）
1. 项目里放一个 `icon.ico`；
2. 打包脚本引用它（Nuitka 用 `--windows-icon-from-ico=icon.ico`）；
3. 图标需要更新时，用本软件重新生成，覆盖旧文件即可。

### 场景 E：网页 favicon 的备用版本（前端）
虽然现代网页 favicon 多用 `.png` 和 `.svg`，但一些老系统和老浏览器仍认 `favicon.ico`。把 logo 转成 `.ico` 放到网站根目录，兼容性更广。

## 7. 输出位置怎么选？单文件和批量的区别

这是**新手最容易搞混**的地方，单独讲清楚。

软件的判断逻辑是：

```
如果（选中的图片数量 > 1）或者（输出位置是一个文件夹）
    → 批量模式
否则
    → 单文件模式
```

### 单文件模式
- 你只选了 1 张图；
- 你选输出位置时，弹的是"保存文件"对话框，能直接指定文件名；
- 生成的 `.ico` 就用你指定的名字和位置。

### 批量模式
- 你选了多张图，或输出位置是文件夹；
- 每个 `.ico` 的名字 = 对应原图的名字（扩展名换成 `.ico`）；
- 全部放在同一个输出文件夹里。

**举个例**：
- 选了 `cat.png`、`dog.jpg`，输出文件夹选 `D:\icons\`；
- 结果：`D:\icons\cat.ico`、`D:\icons\dog.ico`。

**小提示**：如果选了多张图但输出位置填的是一个文件名（理论上不该发生，但万一），软件会自动把输出位置改成那个文件所在的目录，避免混乱。

## 8. 七个尺寸，我到底该勾哪几个？

**最省事的答案**：默认全勾，不用管。

**想搞明白的，看下面**：

| 尺寸 | 典型用途 |
|---|---|
| 16×16 | 任务栏小图标、文件列表、标题栏 |
| 24×24 | 部分系统的中等列表视图 |
| 32×32 | 桌面小图标、工具栏 |
| 48×48 | 桌面中等图标、开始菜单 |
| 64×64 | 大图标视图 |
| 128×128 | 超大图标、部分高清场景 |
| 256×256 | 高清屏、Extra Large Icons 视图、应用商店 |

**勾选原则**：
- **做通用图标** → 全勾。文件会大一点（几十 KB），但任何场景都不糊。
- **只用于任务栏小图标** → 勾 16、24、32 就够，文件更小。
- **只用于高清展示** → 至少勾 256，再配上 48、32 做回退。

**注意**：从 1.6.0 起，**勾了什么就只生成什么**，不会自动补齐。取消勾选 64 和 128，输出里就真的没有这两档。

## 9. "保持宽高比"和"强制透明通道"到底在做什么？

### 保持宽高比（居中填充）

**默认开启**。

图标必须是正方形（16×16、32×32……）。如果你的原图是长方形（比如 800×400），就要做取舍：

- **勾上（默认）**：软件把图等比缩小，让它完整放进正方形画布，四周空出来的地方填**透明**。
  - 800×400 的图 → 缩成 256×128 → 放到 256×256 画布中央 → 上下各 64 像素透明。
  - **优点**：图不变形。**缺点**：有留白。

- **不勾**：软件直接把图**拉伸**成正方形。
  - 800×400 → 强行拉成 256×256 → 圆形变椭圆，人脸变胖。
  - **优点**：铺满，无留白。**缺点**：变形。

**建议**：除非你明确知道原图就是正方形，否则保持勾选。

### 强制添加透明通道

**默认关闭**。

有些图片格式（JPG）本身**没有**透明通道（alpha 通道）。这个选项的作用是：

- **勾上**：转换时强制给图片加上透明通道，即使它原本没有。配合"保持宽高比"时，四周留白能真正透明。
- **不勾**：如果原图是 JPG，转换后透明区域可能变成黑色或白色（取决于系统）。

**建议**：
- 原图是 PNG 且已带透明背景 → 不用勾；
- 原图是 JPG，且你勾了"保持宽高比" → 建议勾上，避免留白处变黑。

## 10. 预览窗口能告诉我什么？

选中文件列表里的某张图，右边会显示：

| 信息 | 含义 |
|---|---|
| 缩略图 | 图片长什么样（最大显示 256×256） |
| 文件名 | 原图文件名 |
| 尺寸 | **原图**的宽×高（不是缩略图尺寸） |
| 格式 | PNG / JPEG / BMP / GIF 等 |
| 模式 | RGB（无透明）/ RGBA（有透明）/ P（调色板）/ L（灰度）等 |

**为什么强调"原图尺寸"？** 因为 1.5.0 之前有个 bug，显示的是缩略图尺寸和 `None` 格式，容易误导。1.5.0 起已修正。

**格式和模式能帮你判断**：
- 格式是 JPEG → 没有透明通道，想要透明留白就勾"强制添加透明通道"；
- 模式是 P（调色板）→ 颜色数有限，转换后可能有点色差；
- 模式是 L（灰度）→ 黑白图。

## 11. 转换历史怎么用？

每次转换（单文件或批量）成功后，都会往历史数据库里写记录。

**查看**：右栏"转换历史"列表，显示格式是 `时间戳 - 源文件名 → 输出文件名`。

**双击某条记录**：弹出详情窗口，显示完整路径和尺寸，并问你是否打开输出文件所在的文件夹。

**清除历史**：点"清除历史记录"按钮，会二次确认（不可撤销）。清完会告诉你删了几条。

**历史存在哪？** 默认是程序目录下的 `conversion_history.db`（SQLite 数据库）。可以用 `.env` 里的 `ICO_DB_PATH` 改位置（详见第 23 节）。

**为什么要有历史？**
- 回头找"我上次那张图转哪去了"；
- 批量转换后核对清单；
- 排查问题时知道之前转过什么。

# 第三部分 · 进阶使用

## 12. 批量转换文件夹的完整流程

**目标**：把一个文件夹里所有图片都转成 ICO。

**步骤**：
1. 点"选择图片文件夹(批量)"；
2. 选中目标文件夹（比如 `D:\raw_icons\`）；
3. 软件会递归扫描（含子文件夹），把所有 PNG/JPG/JPEG/BMP/GIF 列进文件列表；
4. 如果文件夹里没有图片，会弹窗提示"所选文件夹中没有找到图片文件"；
5. 点"选择输出位置"，选一个输出文件夹（比如 `D:\ico_output\`）；
6. 按需调整尺寸勾选和其他选项；
7. 点"开始转换"；
8. 进度条显示进度，完成后弹窗告诉你"已完成 X/Y 个文件"。

**注意事项**：
- 子文件夹里的图片也会被扫描到，但**输出时全部平铺**到一个输出目录（不保留子目录结构）；
- 如果有同名文件（比如 `a\logo.png` 和 `b\logo.png`），后转的会覆盖先转的，输出目录里只有一个 `logo.ico`；
- 部分文件失败不影响其他文件，最后弹窗会告诉你成功几个、失败几个。

## 13. 图标尺寸的行业规范与选择建议

### Windows 官方推荐

微软的图标设计指南建议，一个完整的应用图标至少包含：

| 尺寸 | 用途 |
|---|---|
| 16×16 | 任务栏、标题栏、小列表 |
| 32×32 | 桌面、开始菜单 |
| 48×48 | 中等图标 |
| 256×256 | 大图标、高清屏 |

24、64、128 是"锦上添花"，加上兼容性更好。

### 不同场景的推荐

| 场景 | 推荐尺寸 |
|---|---|
| 桌面快捷方式 | 16, 32, 48, 256 |
| 任务栏固定程序 | 16, 24, 32, 48 |
| 应用商店 / 高清展示 | 全 7 档 |
| 老软件兼容 | 16, 32, 48（不要只给 256） |
| 文件类型图标 | 16, 32, 48 |

### 一个常见误区

**"我只给 256 就行，系统会自己缩。"**

不对。Windows 在 16×16 场景下显示 256 的图，会现场缩小，结果往往**模糊、发虚**，因为系统缩放算法不如你预先用小尺寸专门优化过的好。所以**多档尺寸一起给**才是正确做法。

## 14. 常见图片格式的兼容性说明

| 格式 | 支持 | 透明通道 | 备注 |
|---|---|---|---|
| PNG | ✅ | 有 | 最推荐，无损、支持透明 |
| JPG / JPEG | ✅ | 无 | 照片常用；想要透明留白需勾"强制添加透明通道" |
| BMP | ✅ | 部分 | 老格式，文件大 |
| GIF | ✅ | 部分 | 只取第一帧（本软件不做动画图标） |
| TIFF | ⚠️ | 部分 | Pillow 通常能开，但界面文件框没列，可用"所有文件"手动选 |
| WebP | ⚠️ | 有 | 取决于 Pillow 版本，较新的能开 |
| SVG | ❌ | — | 矢量格式，Pillow 不支持 |
| HEIC / AVIF | ❌ | — | 新格式，需要额外插件，本软件不带 |

**建议**：不确定的话，先转成 PNG 再用本软件处理。

## 15. 转换失败怎么办？错误信息逐条解读

从 1.5.0 起，失败会告诉你**具体原因**，不再只说"转换失败"。

| 错误信息 | 原因 | 解决办法 |
|---|---|---|
| `没有可用的图标尺寸` | 一个尺寸都没勾 | 至少勾一个 |
| `无法识别图片文件` / `cannot identify image file` | 文件损坏，或格式不支持 | 换一张图，或先转成 PNG |
| `height and width must be > 0` | 极端长宽比（1.5.0 已修） | 升级到 1.5.0+ |
| `ICO文件尺寸不匹配，期望: [...], 实际: [...]` | 生成结果不对 | 一般是 Pillow 版本问题，反馈到 GitHub Issues |
| `生成的不是有效的ICO文件` | 写入过程出错 | 检查磁盘空间、输出路径权限 |
| `Permission denied` | 输出文件被占用（比如正在看图标的资源管理器） | 关掉占用程序，换个输出位置 |

## 18. 核心算法：图片是怎么变成 ICO 的

### 输入
- `image_path`：源图片路径
- `output_path`：输出 `.ico` 路径
- `sizes`：尺寸列表，如 `[16, 32, 48]`
- `preserve_aspect`：是否保持宽高比居中填充
- `add_transparency`：是否强制加透明通道

### 步骤

**1. 规范化尺寸**（`normalize_sizes`）
- 去掉非正整数、去重、升序；
- 只保留 1~256 之间的值；
- 返回 `[16, 24, 32, ...]` 这样的列表。

**2. 展开尺寸**（`expand_sizes`，1.6.0 起）
- **所见即所得**：勾了什么就是什么，不补齐；
- 1.0~1.5 的"阶梯补齐"逻辑移到 `legacy_ladder_expand()`，仅供旧设置迁移用。

**3. 打开源图**
- 用 Pillow 打开；
- 如果原模式不是 RGBA：
  - 勾了"强制透明"或原格式是 JPEG → 转 RGBA；
  - 否则转 RGB。

**4. 逐尺寸渲染方形帧**（`render_frame`）

保持宽高比时：
```
ratio = min(size / img.width, size / img.height)
new_w = max(1, round(img.width * ratio))   ← 1 像素保底
new_h = max(1, round(img.height * ratio))
resized = img.resize((new_w, new_h), LANCZOS).convert('RGBA')
canvas = Image.new('RGBA', (size, size), (0,0,0,0))
canvas.paste(resized, ((size-new_w)//2, (size-new_h)//2))
```

不保持宽高比时：
```
img.convert('RGBA').resize((size, size), LANCZOS)
```

**5. 一次性写入 ICO**
```python
frames[-1].save(
    output_path,
    format='ICO',
    sizes=[(size, size) for size in targets],
    append_images=frames[:-1],
)
```

> **为什么用"最后一帧 .save + append_images"这种写法？**
> Pillow 的 ICO 保存约定：第一帧作为主帧，其余通过 `append_images` 附加。用 `frames[-1]` 只是代码风格，关键是**全部帧一次性给出**，而不是"先写一帧再重开文件追加"——后者会把正在读的文件截断，并且 Pillow 只保留 ≤ 第一帧尺寸的档位，导致丢帧（1.5.0 修复的 bug）。

**6. 校验**
- `read_ico_sizes()`：直接解析 ICO 文件头的目录项，返回 `{(w,h), ...}`；
- 检查目标尺寸是否全部存在；
- 再用 Pillow 真正 `load()` 一次解码像素；
- 任何一步失败 → 删掉半成品文件，写入 `last_error`，返回 `False`。

## 19. ICO 文件格式技术细节

### 文件结构

```
┌──────────────────────┐
│ ICONDIR (6 字节)     │
│  - reserved (2B) = 0 │
│  - type     (2B) = 1 │  (1 = icon, 2 = cursor)
│  - count    (2B) = N │  图像数量
├──────────────────────┤
│ ICONDIRENTRY[0] (16B)│
│ ICONDIRENTRY[1] (16B)│
│ ...                  │
│ ICONDIRENTRY[N-1]    │
├──────────────────────┤
│ 图像数据 0           │
│ 图像数据 1           │
│ ...                  │
└──────────────────────┘
```

### ICONDIRENTRY 字段（16 字节）

| 偏移 | 大小 | 含义 |
|---|---|---|
| 0 | 1 | 宽（0 表示 256） |
| 1 | 1 | 高（0 表示 256） |
| 2 | 1 | 调色板颜色数（0 = 无） |
| 3 | 1 | 保留（0） |
| 4 | 2 | 颜色平面数（PNG 帧通常 1） |
| 6 | 2 | 位深（PNG 帧通常 32） |
| 8 | 4 | 数据大小（字节） |
| 12 | 4 | 数据偏移（从文件头算起） |

### 为什么最大只能 256×256？

宽和高各占 **1 字节**，范围 0~255。ICO 规范约定 **0 表示 256**。所以格式上最大就是 256×256，512 无法表达。

### 图像数据格式

- **Vista 及以后**：内嵌 PNG（32bpp RGBA），体积小、有透明；
- **XP 及以前**：内嵌 BMP（DIB），带一个 AND 掩码做透明。

本软件生成的是 **PNG 帧**，所以 **Windows XP 不识别**。如果需要兼容 XP，得改成 BMP 帧（当前未实现）。

## 20. 尺寸语义的演进（1.5.0 → 1.6.0）

这是理解本软件行为的关键，单独讲。

### 1.0~1.5：界面只有 256，但输出有 7 档

那个年代，界面只给一个勾选框"256×256"。用户勾上后，实际输出的是 **16,24,32,48,64,128,256 全套**——因为代码里有个"阶梯补齐"逻辑：

```
输出尺寸 = 所选尺寸 ∪ { 阶梯中 ≤ max(所选尺寸) 的尺寸 }
```

勾 256 → `{256} ∪ {16,24,32,48,64,128}` = 全 7 档。

**为什么这么设计？** 因为 Pillow 保存 ICO 时默认就会生成这套阶梯，早期开发者干脆顺着这个行为走。

**问题**：用户以为"我只勾了 256"，其实生成了 7 档；而且没法只生成 256。

### 1.6.0：界面全列出，所见即所得

- 界面列出全部 7 档，默认全勾；
- `expand_sizes()` 改为**严格按勾选**；
- 默认全勾时输出仍是 7 档，**老用户升级无感知**；
- 想要只生成 256？取消其他 6 个勾选即可。

### 旧设置怎么办？

1.0~1.5 的 `settings.json` 里 `sizes` 可能只有 `[256]`，如果 1.6.0 直接按 `[256]` 恢复，界面就只勾 256，用户会以为"我的图标怎么从 7 档变 1 档了"。

所以 1.6.0 加了迁移逻辑：
- `settings.json` 里有 `sizes_exact: true` → 新设置，按原样恢复；
- 没有这个键 → 老设置，用 `legacy_ladder_expand()` 还原成"当时真正生成的尺寸"，再勾选；
- 迁移结果立即写回，并补上 `sizes_exact: true`。

`[256]` → 迁移后全选 7 档 → 用户看到的就是他升级前实际得到的东西。

## 22. 数据库结构

**表名**：`conversion_history`

```sql
CREATE TABLE IF NOT EXISTS conversion_history (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    source_path  TEXT NOT NULL,
    output_path  TEXT NOT NULL,
    sizes        TEXT NOT NULL,   -- 逗号分隔，如 "16,32,48"
    timestamp    DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**字段说明**：
- `sizes` 存成逗号分隔字符串，方便展示；
- `timestamp` 自动填当前时间；
- **字段名不要改**，否则老数据丢失。

**操作**：
- `add_record(source, output, sizes)`：插入一条；
- `get_history(limit=50)`：按时间倒序取最近 N 条；
- `clear_history()`：删全部，返回删除条数。

**位置**：默认 `程序目录/conversion_history.db`，可用 `.env` 的 `ICO_DB_PATH` 改。

## 24. 打包与分发

### Nuitka（当前使用）

脚本：`0_nuitka_pyqt5_clang_auto.bat`

关键参数：
```
--standalone
--windows-console-mode=disable
--windows-icon-from-ico=icon.ico
--include-data-files=icon.ico=icon.ico
--follow-imports
--enable-plugin=pyqt5          ← 必须是 pyqt5，不是 pyside6
--jobs=4
--clang
--remove-output
--output-dir=build_output
```

**为什么 `--include-data-files=icon.ico=icon.ico` 不能删？**
程序运行时会读 `<exe 同目录>\icon.ico` 作为窗口/任务栏图标。不打包进去，程序会自己画一个蓝色圆圈的占位图标，用户看到的就是假图标。

**为什么必须是 `--enable-plugin=pyqt5`？**
本项目用 PyQt5，不是 PySide6。插件不匹配时，Qt 的 `platforms/qwindows.dll` 等不会被正确收集，打出来的 exe 可能直接起不来。

**脚本约定**：
- 纯 ASCII + CRLF + 无 BOM（cmd.exe 按字节解析 .bat，中文注释容易踩坑）；
- 开头 `cd /d "%~dp0"`，保证相对路径正确；
- 编译前检查 exe 是否在运行（占用会导致链接失败）。

### PyInstaller（旧方式）

配置文件：`Image_To_Icon_Converter.spec`
（当前不推荐，保留兼容。）

### 分发

**整个 `build_output\Image_To_Icon_Converter.dist\` 目录一起给**，不要只拷 exe。

## B. 常见问题 FAQ

**Q1：为什么我转换后图标显示很模糊？**
A：检查是不是只勾了 256×256。16×16 场景显示 256 会现场缩小，容易模糊。建议全勾。

**Q2：转换后图片变形了？**
A：检查"保持宽高比"是否被取消。勾上即可。

**Q3：透明背景变成黑色了？**
A：原图可能是 JPG（无透明通道）。勾上"强制添加透明通道"再转。

**Q4：生成的 ICO 在 Windows XP 上不显示？**
A：本软件生成的是 PNG 压缩帧，XP 不识别。需要 BMP 帧，当前未实现。

**Q5：批量转换后文件少了？**
A：可能有同名文件互相覆盖（比如 `a\logo.png` 和 `b\logo.png` 都输出成 `logo.ico`）。输出目录是平铺的，不保留子目录结构。

**Q6：设置下次启动还在吗？**
A：在。所有设置实时保存，下次启动自动恢复。

**Q7：程序目录在哪？**
A：如果是源码运行，就是 `Image_To_Icon_Converter.py` 所在目录；如果是 exe，就是 exe 所在目录。

**Q8：怎么改历史数据库位置？**
A：在 `.env` 里加 `ICO_DB_PATH=D:\your\path\history.db`。

**Q9：转换很慢？**
A：单张图通常几百毫秒。批量时进度条会动。如果特别慢，检查是不是超大图（比如 10000×10000）。

**Q10：能转 SVG 吗？**
A：不能。先转成 PNG。
